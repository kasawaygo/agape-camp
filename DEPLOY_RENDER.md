# AGAPE CAMP: подготовка к Render

## Что уже настроено

- Render собирает Go-приложение командой `go build` и запускает его как web service.
- Порт берётся из `PORT`, который Render назначает автоматически.
- `/healthz` проверяет доступность приложения и соединение с PostgreSQL; путь уже указан в `render.yaml`.
- Secure cookie включается для Render/production и задаётся в Blueprint явно.
- Настройки базы читаются из окружения, а значения пользователя и пароля корректно экранируются при сборке PostgreSQL URL.
- Секретные переменные помечены `sync: false`; их значения не записаны в файлы проекта.

## Перед созданием сервиса

1. Убедитесь, что проект находится в GitHub репозитории, доступном вашему аккаунту Render. Папка проекта должна включать `render.yaml`, `go.mod`, `go.sum`, `main.go` и каталог `web`.
2. В Supabase откройте **Project Settings → Database → Connection info** и подготовьте значения для `DB_HOST`, `DB_USER`, `DB_PASSWORD`. Используйте данные подключения к PostgreSQL (при необходимости — Session pooler), а не ключи Supabase API.
3. Подготовьте отдельный сильный пароль администратора для `ADMIN_PASSWORD`.
4. Создайте случайный длинный секрет для `SESSION_SECRET` (не менее 32 случайных байт). Не используйте пароль администратора как секрет сессии.

## Создание сервиса

1. В Render выберите **New → Blueprint** и подключите репозиторий с проектом.
2. Проверьте, что Blueprint показывает сервис `agape-camp` и план `Free`.
3. Перед запуском заполните запрошенные значения `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `ADMIN_PASSWORD` и `SESSION_SECRET` в панели Render. Не вставляйте их в `render.yaml`, GitHub или переписку.
4. Запустите создание сервиса. Публикация ещё требует отдельного согласования; эта инструкция не запускает её.
5. После создания проверьте логи. Сервис должен сообщить об успешном подключении к Supabase, а `/healthz` должен вернуть `200`.
6. Откройте адрес `*.onrender.com`, проверьте форму регистрации и вход в `/admin/login`.

## Переменные окружения

| Переменная | Значение |
|---|---|
| `PORT` | Назначается Render автоматически; вручную не задавать. |
| `DB_HOST` | Host PostgreSQL из Supabase. |
| `DB_PORT` | `5432` в Blueprint; если Supabase выдал иной порт для выбранного способа подключения, укажите его в Render. |
| `DB_USER` | Пользователь PostgreSQL из Supabase. |
| `DB_PASSWORD` | Пароль PostgreSQL из Supabase. Секрет. |
| `DB_NAME` | `postgres` по умолчанию в Blueprint; проверьте значение проекта Supabase. |
| `DB_SSLMODE` | `require`. |
| `ADMIN_PASSWORD` | Отдельный сильный пароль админки. Секрет. |
| `SESSION_SECRET` | Длинное случайное значение для подписи cookie. Секрет. |
| `COOKIE_SECURE` | `true` для HTTPS. |
| `APP_ENV` | `production`. |

## Важное замечание по защите входа

Ограничение неудачных попыток входа хранится в памяти одного процесса. На бесплатном веб-сервисе Render оно не является общим для нескольких экземпляров и сбрасывается после перезапуска. Перед широким публичным запуском стоит перенести счётчик в постоянное общее хранилище или добавить внешний rate limit.

`.env` содержит локальные секреты. Не публикуйте его и не копируйте его содержимое в Render YAML или GitHub. В репозитории `.env` исключён через `.gitignore`.
