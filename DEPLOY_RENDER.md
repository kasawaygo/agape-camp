# AGAPE CAMP и TRES DIAS: Render

## Что уже настроено

- Blueprint описывает два отдельных бесплатных веб-сайта: `agape-camp` и `agape-tres-dias`.
- Второй сайт открывает TRES DIAS сразу с главной страницы; формы доступны участнику и служителю.
- Оба сайта используют одну Go-программу и общую базу Supabase, но у TRES DIAS будет отдельный адрес Render.
- Переменные базы, пароль администратора и ключ сессии второго сервиса ссылаются на первый через Blueprint; секреты не записаны в файлы проекта.
- Render собирает Go-приложение командой `go build` и запускает его как web service.
- Порт берётся из `PORT`, который Render назначает автоматически.
- `/healthz` проверяет доступность приложения и соединение с PostgreSQL; путь уже указан в `render.yaml`.
- Secure cookie включается для Render/production и задаётся в Blueprint явно.
- Настройки базы читаются из окружения, а значения пользователя и пароля корректно экранируются при сборке PostgreSQL URL.
- Секретные переменные помечены `sync: false`; их значения не записаны в файлы проекта.

## Отдельный адрес TRES DIAS

В Blueprint добавлен второй бесплатный сервис с именем `agape-tres-dias`. Его стартовая страница автоматически открывает TRES DIAS, а анкеты отправляются в ту же базу, которую показывает раздел **TRES DIAS 2027** в админке лагеря. Адрес после создания сервиса: `https://agape-tres-dias.onrender.com/`.

Если Render не создаст новый сервис автоматически после отправки изменений в GitHub, откройте Blueprint `agape-camp` в Render и нажмите **Sync** / **Manual Sync**, затем проверьте, что новый сервис создаётся на плане **Free**. Значения секретов второй службе подтягиваются из переменных `agape-camp`; вводить их в репозиторий не нужно.

Обе бесплатные службы делят месячный лимит бесплатных часов Render в рабочем пространстве. Когда они не получают посетителей 15 минут, Render может их усыпить; первый посетитель разбудит нужный сайт автоматически. Схема не создаёт вторую базу.

## Синхронизация двух сайтов в Render

1. Отправьте изменения проекта в ветку `main` репозитория `kasawaygo/agape-camp`.
2. Откройте Render Dashboard → Blueprint `agape-camp`. Если синхронизация не началась автоматически, нажмите **Sync** / **Manual Sync**.
3. Проверьте, что Blueprint показывает службы `agape-camp` и `agape-tres-dias`, обе на **Free**.
4. Просмотрите изменения и синхронизируйте Blueprint. Новая служба получает настройки базы и администратора как ссылки на первую службу; секреты не вставляйте в GitHub.
5. Дождитесь успешного запуска обеих служб и проверьте `/healthz`.
6. Проверьте сайт лагеря и отдельный сайт TRES DIAS. Главная страница второй службы должна открывать анкеты TRES DIAS.

## Переменные окружения

| Переменная | Значение |
|---|---|
| `PORT` | Назначается Render автоматически; вручную не задавать. |
| `DB_HOST` | Host PostgreSQL из Supabase. |
| `DB_PORT` | `5432` в Blueprint; если Supabase выдал иной порт для выбранного способа подключения, укажите его в Render. |
| `DB_USER` | Пользователь PostgreSQL из Supabase. |
| `DB_PASSWORD` | Пароль PostgreSQL из Supabase. Секрет. |
| `DB_NAME` | `postgres` по умолчанию в Blueprint; проверьте значение проекта Supabase. |
| `DB_SSLMODE` | `require`. |
| `ADMIN_PASSWORD` | Отдельный сильный пароль админки. Секрет. |
| `SESSION_SECRET` | Длинное случайное значение для подписи cookie. Секрет. |
| `COOKIE_SECURE` | `true` для HTTPS. |
| `APP_ENV` | `production`. |

## Важное замечание по защите входа

Ограничение неудачных попыток входа хранится в памяти одного процесса. На бесплатном веб-сервисе Render оно не является общим для нескольких экземпляров и сбрасывается после перезапуска. Перед широким публичным запуском стоит перенести счётчик в постоянное общее хранилище или добавить внешний rate limit.

`.env` содержит локальные секреты. Не публикуйте его и не копируйте его содержимое в Render YAML или GitHub. В репозитории `.env` исключён через `.gitignore`.
